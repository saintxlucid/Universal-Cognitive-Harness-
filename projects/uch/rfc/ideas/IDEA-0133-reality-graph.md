# IDEA-0133 — Reality Graph

- **Status:** Idea (SOP-08 stage 1; no code)
- **Origin:** 2026-08-01 round-21 intake — "everything should first
  become Entity, Relation, Property, Constraint, Event, Goal,
  Observation, Evidence, Assumption, Hypothesis, Decision — NOT
  markdown, NOT text, NOT code. Then export into Markdown, JSON, Graph,
  Mermaid, Database, Mindmap, Flowchart, Code, Documents." Layer 0 of
  the engine stack; the user's "favorite insight" (reality ≠
  representation).
- **Related:** IDEA-0056 (cognitive object model — classes + lifecycle),
  IDEA-0050 (knowledge fabric), RFC-0004 (CIR — the kernel never sees
  English), IDEA-0047 (UER — causal layer), IDEA-0049 (storage engine),
  IDEA-0057 (cognitive query language — the query surface), connectome
  (association), VISION sec 1 (truth vs representation)

## Motivation

A markdown doc, a graph, a diagram, a UML, a database, natural
language, math, and Python code can all describe the SAME thing —
different representations, same reality. The claim: UCH needs a
substrate where the reality classes are first-class nodes and every
representation is a derived export of the same underlying reality —
never the primary artifact.

## The corpus cannot cover it because

COM (IDEA-0056) gives object classes + a uniform lifecycle but no graph
vocabulary (Entity / Relation / Property / Constraint are not node and
edge kinds); the fabric (IDEA-0050) is a typed-artifact graph, not the
ground truth those artifacts represent; CIR is itself a representation
(an instruction form); connectome edges are activation weights, not
reality relations. No artifact says "this markdown is a view of node X"
— exports are generated by hand or by repo-indexer, not derived from a
reality graph, and no round-trip (representation → reality → representation)
exists.

## Proposal sketch

- Reality graph as Layer 0: node kinds = Entity, Event, Goal,
  Observation, Evidence, Assumption, Hypothesis, Decision; Relation as
  edge kind; Property, Constraint as attribute kinds on nodes/edges.
- Representation nodes: every file/artifact registers as a
  representation with a `renders` edge to the reality it describes;
  markdown / JSON / mermaid / DB / mindmap / code are render targets.
- Export semantics: render targets are derived; edits flow back through
  the same substrate (round-trip, CIR-style); the reality graph is the
  single source of truth the exports re-project.
- Relationship to corpus: the graph is the payload layer under the
  fabric (IDEA-0050) — fabric = typed artifacts, reality graph = the
  ground truth they represent; COM instances are nodes with the
  IDEA-0056 lifecycle; Perspective Engine (IDEA-0137) views are render
  targets.

## Risk assessment

- Graph theater: without a round-trip writer for at least one format
  (markdown ↔ graph), the graph is a database no one reads. Anchor:
  repo-indexer + the spec-version gate are natural first consumers.
- Re-description: entities must be shared (identity via COM), not
  per-export copies.

## Where it lands

Extension of `src/workspace-graphs/` + IDEA-0049 storage; CQL
(IDEA-0057) is its query surface.

## Code impact

None until a markdown ↔ graph round-trip prototype; schema definition
is a spec exercise first.

## Next stage

Define the 12-class schema; prototype a single markdown document ↔
graph round-trip; then register repo-indexer output as representations.
