# UCH × Codex — Standalone Integration

Part of the UCH Hive Mind (`design/UNIVERSAL-INTEGRATION.md`). Codex mirrors
Claude Code's hook model, adds first-class OTel export in `config.toml`, and
persists rich rollouts (including reasoning items) — the strongest passive
capture surface of all runtimes.

## 1. Mechanism of integration (verified, July 2026)

| Surface | Mechanism | What UCH does |
| --- | --- | --- |
| Live capture | `[hooks]` in `~/.codex/config.toml` or sidecar `hooks.json` (command hooks) | SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, SubagentStop, PreCompact → HiveEvents (no SessionEnd event exists; detected via Stop + rollout tail) |
| COT | rollout `response_item` content blocks type `reasoning`; `codex exec --json` item type `reasoning` | reasoning vault; recommend `model_reasoning_summary=detailed`; raw COT requires `show_raw_agent_reasoning=true` (opt-in) |
| Passive replay | daemon tail of `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` + `state.sqlite` index | full prompts, responses, reasoning, tool calls, outputs, token counts |
| OTel | `[otel.trace_exporter.uch]` → `otlp-http` at `http://127.0.0.1:4318/v1/traces` | spans → TraceLedger via daemon OTLP receiver (M2) |
| MCP | `[mcp_servers.uch]` in `config.toml` | UCH MCP server → all 25+ cognitive tools |
| Instructions | AGENTS.md hierarchy + `@import` | hive context doc generated by `uch hive init --codex` |
| Drive | `codex exec --json` headless | UCH background agents run Codex one-shots |
| Background | `command_execution` items (command, exit_code, aggregated_output) + PreToolUse/PostToolUse | agent shell commands → `background.process` |

## 2. Hooks configuration (generated by `uch hive init --codex`)

`~/.codex/config.toml` (user) or `.codex/config.toml` (project):

```toml
[hooks]

[[hooks.SessionStart]]
matcher = "*"
[[hooks.SessionStart.hooks]]
type = "command"
command = "node ~/.uch/hooks/codex-hook.mjs SessionStart"
timeout = 10

[[hooks.UserPromptSubmit]]
matcher = "*"
[[hooks.UserPromptSubmit.hooks]]
type = "command"
command = "node ~/.uch/hooks/codex-hook.mjs UserPromptSubmit"
timeout = 10

[[hooks.PreToolUse]]
matcher = "*"
[[hooks.PreToolUse.hooks]]
type = "command"
command = "node ~/.uch/hooks/codex-hook.mjs PreToolUse"
timeout = 30

[[hooks.PostToolUse]]
matcher = "*"
[[hooks.PostToolUse.hooks]]
type = "command"
command = "node ~/.uch/hooks/codex-hook.mjs PostToolUse"
timeout = 30

[[hooks.Stop]]
matcher = "*"
[[hooks.Stop.hooks]]
type = "command"
command = "node ~/.uch/hooks/codex-hook.mjs Stop"
timeout = 30
```

Contract (Codex-specific):

- **No `SessionEnd` event exists in Codex** (supported set: `PreToolUse`,
  `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`,
  `SessionStart`, `SubagentStart`, `SubagentStop`, `UserPromptSubmit`, `Stop`).
  Session termination is detected via the `Stop` hook plus rollout-tail EOF /
  `session_meta` records.
- Common stdin JSON: `session_id`, `transcript_path` (may be null), `cwd`,
  `hook_event_name`, `model` (Codex extension), `permission_mode`; turn-scoped
  hooks add `turn_id`. Use `turn_id` as `provenance.nativeIds.turnId`.
- Only `type: "command"` handlers run; `async` handlers are skipped; default
  timeout 600 s (override per hook). `commandWindows` for Windows shells.
- Matchers: tool names (`Bash`, `apply_patch`, `mcp__<server>__<tool>`),
  SessionStart `startup|resume|clear|compact`, PreCompact `manual|auto`.
- UCH is non-blocking (no `hookSpecificOutput`) — emit to spool, exit 0.
- `history.persistence = "save-all"` (default) must stay on so rollouts are
  available for replay.

## 3. Rollout tail (passive capture, source of truth)

```
~/.codex/sessions/YYYY/MM/DD/rollout-{ts}-{uuid}.jsonl
```

Envelope: `{ "timestamp": "…", "type": "<record-type>", "payload": { … } }` with
record types:

| `type` | `payload` | → HiveEvent |
| --- | --- | --- |
| `session_meta` | `session_id`, `cwd`, `model_provider`, `cli_version` | `session.start` meta |
| `response_item` / `payload.type = "message"` | role assistant, `content[]` blocks `text` / `reasoning` / `refusal` | `assistant.message` / `reasoning` |
| `response_item` / `payload.type = "function_call"` | name (`exec_command`, `apply_patch`, `custom_function`, `mcp_call`), `arguments` | `tool.call` (+ `background.process` for exec_command) |
| `response_item` / `payload.type = "function_call_output"` | `call_id`, `output` | `tool.result` |
| `event_msg` / `payload.type = "user_message"` | text | `user.prompt` |
| `event_msg` / `payload.type = "agent_message"` | text | `assistant.message` |
| `event_msg` / `payload.type = "token_count"` | input/output/cached | `meta.tokens` |

Sidecar `state.sqlite` (ThreadMetadata: title, token usage, git SHA/branch,
created/updated ms) — used for session listing/titles; `~/.codex/history.jsonl`
(`{session_id, ts, text}`) as the session index. Rollout files are append-only
and tail-friendly; keep per-file byte cursors.

Defensive parsing required: older versions used `item_type` / `assistant_message`
field names — accept both, pin nothing.

## 4. OTel export (M2)

```toml
[otel]
trace_exporter = "uch"

[otel.trace_exporter.uch]
type = "otlp-http"                    # or otlp-grpc
endpoint = "http://127.0.0.1:4318"    # hive daemon OTLP receiver
protocol = "json"
headers = { Authorization = "Bearer <hive-token>" }
```

Daemon maps spans into TraceLedger (ADR-002 schema); `turn_id` in span
attributes joins spans to hook events.

## 7. Drive (hive → Codex)

```bash
codex exec --json --full-auto -C <workdir> "task prompt"   # JSONL events incl. reasoning items
codex exec --json --ephemeral "one-shot"                   # no rollout persisted
codex resume --last                                        # continue latest session
```

UCH background agents wrap `codex exec --json`, mirror events to the ledger,
and write a `handoff` on completion. For in-process embedding, the
`@openai/codex` SDK exposes the same session/stream/trace surface
(`CodexClient`, `session.respond()`, stream events incl. `trace.trace_update`,
OTel instrumentation).
